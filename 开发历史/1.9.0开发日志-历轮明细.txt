A2 点击形象 GIF → 聊天窗口直接可输入
────────────────────────────────────────────────────────────────
【根因】以前是 show() → activateWindow() → **立刻** setFocus()。
Windows 的 activateWindow() 是异步的（要等 WM_ACTIVATE 回来），紧跟着的
setFocus() 先落在旧焦点上，随后窗口激活又把焦点收回，输入框就丢了焦点 ——
表现正是「光标已经在闪，但打不了字，得再点一下输入框」。
【修法】_input_field_focus() 改成：先 raise_/activateWindow，再
  QTimer.singleShot(0) 与 (80) 两段延时 setFocus(Qt.OtherFocusReason)；
  新增 _focus_input_now()，只在输入框**可见且未禁用**时抢焦点
  （「总结旧话题」期间输入框被临时禁用，那时不该硬抢）。
【线程前提（重要）】_on_pet_clicked 一定跑在主线程 —— 子进程模式下
  pet_clicked 由 PetProxy 的 queued signal 投递回主线程，直接渲染模式同线程。
  所以这里用 QTimer.singleShot 是合法的，与 1.8.2/1.8.5 那个
  「子线程里 QTimer 永不触发」的坑不是一回事。自测里有线程断言守着，
  以后别照搬那段结论把这里改坏。

A3 气泡几何重做（数字见《UI几何模型.txt》）
────────────────────────────────────────────────────────────────
【根因】旧写法 <td align="right"> 同时管了「气泡靠边」和「文字对齐」，
于是**换行后的续行也右对齐**（左边参差），不符合阅读习惯。
【修法】外层 td 只负责把气泡块推到头像这一侧；真正装内容的是内层
  **无 width 的 table**（Qt 里只有 table 会按内容自适应，1.8.2 实测结论），
  内层 td 用 align="left" → 气泡内所有行齐左；底色/内边距(8×12)/圆角(12)
  一并挪到内层 td，无底色(transparent)时不下发内边距，保持旧观感。
【实测】短消息气泡宽 61px（内容宽 400），多行逐行起点离散度 0px
  （旧写法 312px）；有底色的短气泡 70px vs 旧写法 46px，差的 24px 就是
  内层 td 的左右各 12px 内边距。
【★ 一条被实测推翻的预设，留档别再照抄】原以为「span 底色是锯齿状，
  短行只铺到文字末尾」——Qt 实测**不成立**，行内 span 的底色同样只覆盖
  文字范围、看着也是矩形。所以这次底色挪到 td 的实际收益是**内边距生效**，
  不是「把锯齿背景变成矩形」。

Y4a 文件卡片圆角：做完了，顺带查出一个**一直没被发现的大问题**
────────────────────────────────────────────────────────────────
【★ 重要发现：卡片尺寸从来没生效过】
  实测（把卡片底色临时换成亮绿色再抓屏）：卡片在应用里被 Qt 画成
  **326×43 px**，而不是 `CARD_*_CM` 想要的 170×57 —— 因为卡片嵌套在
  「<table width="100%"> 的 <td>」里，**Qt 会忽略嵌套表格的 width/height**。
  也就是说 1.8.2「3cm×1cm」、1.8.4「放大到 4.5×1.5cm」这两轮改动
  **在真实界面上从未生效**；既有 `_test_file_card_182` 只量了"单独渲染"的卡片，
  所以一直没暴露。（你看界面觉得"大小合适"，其实是那条 8.6cm 宽的长条。）
  → 本轮**不动尺寸**（改尺寸要重排整行布局、风险大且你在离线状态没法确认），
    只做圆角，尺寸问题在此留档。

【做法（与气泡同一套自绘，几何规则这次量准了）】
  新增 `_painted_box(frame, cell)`：**Qt 实际绘制单元格底色的矩形** =
  `frameBoundingRect` 平移 −(padx, pady)，pad =（frame 尺寸 − 文字块并集尺寸）/2。
  为什么不能用"文字块并集直接外扩"：并集的**位置**在嵌套表格里不可靠
  （frame.x 与 union.x 会差一整个内边距），但 frame 的**尺寸**是准的。
  两处实测都精确吻合：
      气泡 frame(191,21,154,31) union(191,21,130,15) pad(12,8) → (179,13) ✓
      卡片 frame( 16,17,326,43) union( 64,17,308,35) pad( 9,4) → (  7,13) ✓
  卡片识别：**显式设了高度的 1×1 表格**（气泡没有显式高度）。
  ⚠ 坑：PySide6 里 `.type() == 0` 与枚举比较**不成立**，必须写
  `QTextLength.VariableLength`，否则气泡也会被当成卡片、白底盖掉气泡
  （我踩了一次，测试抓出来了）。
  `file_card_html` 的 `bgcolor="#ffffff"` 已去掉 —— 白底与圆角都交给自绘。

【实测】卡片矩形与文字块完全吻合、四角 0/4 残留白色、内边距处是白色。

PTRTS1.9.0 —— 第六轮：三个窗口四角圆角完成（+ 一个 QSS 认知纠正）
==================================================================
【本项来自你的批注】"最好聊天窗口，左侧栏，设置界面都做成四个圆角。"

────────────────────────────────────────────────────────────────
【★ 一个重要纠正：样式表里的 border-radius 其实**从来没生效过**】
────────────────────────────────────────────────────────────────
`chat_widget._style_sheet()` 里一直写着
    ChatWidget { background: …; border: 1px solid #ccc; border-radius: 12px; }
`settings_window._apply_style()` 里也一直写着
    SettingsWindow { background: #fafafa; …; border-radius: 12px; }
**两处都从没生效**，只是以前窗口是不透明的、那块方底来自窗口系统，
看着"有底色"，所以没人发现。实测（本轮做的对照实验）：

  A. 自定义 Python 类名选择器 `MyWin {…}`        → **不匹配**，什么都不画
  B. 不写选择器 `background: …`                  → 只画到了**子控件**上
  C. `setObjectName` + `#id` 选择器              → 同样不画
  D. `QWidget {…}`（Qt 自带类名）                → 同样只画到子控件
  ★ 而且：**顶层自定义窗口的 QSS 背景本身就不会被绘制**
    （即使开了 `WA_StyledBackground`——我四种组合都试过了）

  结论：在顶层自定义窗口上，QSS 做圆角这条路走不通。
  （顺带说明为什么以前"看着没问题"：`WA_TranslucentBackground=False` 时，
   窗口系统会给一块不透明的方底，看起来就像有背景色。）

────────────────────────────────────────────────────────────────
【最终做法：透明底 + 自己画圆角矩形（和气泡/卡片同一套思路）】
────────────────────────────────────────────────────────────────
· 三个窗口都改成 `WA_TranslucentBackground = True`；
· 各自加一个 `paintEvent`，用 `drawRoundedRect(rect, 12, 12)` 画自己的底色：
    聊天窗口  → 用配置里的 `ui.ui_bg_color`（跟着「个性化」页变）
    左侧栏    → #f0f0f2
    设置窗口  → #fafafa
  （边框也一起画，1px）
· `WA_StyledBackground = True` 也加上了（无害，且语义正确）。

【★ 过程中抓到的第二个坑（已修）】
  侧栏那句 `SidebarWindow { background: … }` 原来写在 **ChatWidget 的样式表**里 ——
  而侧栏是**独立顶层窗口**，收不到别人的样式表。以前靠"窗口不透明底"看着正常，
  一开透明底就**整块变透明**（第一次抓屏就抓到了：中心 alpha=0）。
  现在侧栏的底色在自己 `__init__` 里设，并在 `paintEvent` 里自绘。

────────────────────────────────────────────────────────────────
【实测（抓屏量像素，_test_a190.py 里常态保留）】
────────────────────────────────────────────────────────────────
                四角 alpha   中间 alpha   边距底色
   聊天窗口         0            255        #aaffff（= 配置的 ui_bg）
   左侧栏           0            255        #f0f0f2
   设置窗口         0            255        #fafafa
  → 四角透明＝圆角；边距被自己的底色画满＝**不会透出桌面**（这是开透明底最大的
    风险点，专门加了断言守住）。

【怎么回退（如果观感不对）】
  把三个窗口 `__init__` 里的 `WA_TranslucentBackground` 改回 False、
  并删掉各自的 `paintEvent` 即可（都带 ★ 1.9.0 注释）。

【先说一句：这个目标是两半，本轮做的是**上半**（工具本体），下半留到下一轮】
  上半：把"看文件"升级成一个统一的、会自己选路的工具  ← 本轮完成
  下半：聊天里用户发的 / LLM 发的图片与文件**也全部走它**，不再各走各的多模态链路
        （要动 session 的消息构造 + main_window 的上传/推送链路，风险和面都更大）

────────────────────────────────────────────────────────────────
【设计：为什么是"一个入口 + 自动选路"】
────────────────────────────────────────────────────────────────
以前"看文件"有两条互不相干的链路：
  · 聊天里用户发图 → 视觉识别 / 多模态直传（写在 session/main_window 里）
  · LLM 主动看文件 → file_ops.read（**图片只回尺寸元信息**，等于没眼睛）
你要求的正是把这两条合成一条。所以新增 `tools/file_view.py`，对外只有一个入口：

    view_file(path, method="auto", pages="", max_chars=0, prompt="") -> dict

  · method（查看方式）: auto | multimodal | vision | stt | text
  · pages （查看位置）: ""（默认/抽样）| "3" | "3-5" | "1,4,7"
       PDF 按页、PPT 按张、Excel 按工作表
  · 返回 dict：success / kind / method / pages / text / note / meta
    （meta 里带 size / size_str / is_small / pages_total —— 你说的"文件大小用于
      判断是不是大文件"就在这里，模型也看得见）

【自动选路规则（method=auto）】
    图片        → 多模态直读（视觉模型**如实描述**）
    文本/代码   → 原文；超过 20000 字自动"头 2/3 + 尾 1/3"抽样并写明省略多少字
    PDF         → 按页：**先抽文本**；某页文本 < 30 字（扫描件/漫画/图表）就
                  把那一页渲染成图走视觉；超过 8 页自动抽样（首页+均匀中间+末页）
    Word        → 原文（Word 无固定分页，pages 不适用）
    PPT/Excel   → 按张/按表返回文本
    音频        → STT 转写
    视频        → ffprobe 元信息 + 音轨 STT（逐帧视觉暂未实现，已在 note 里写明）
    未知二进制  → 文件头 hex + 可打印字符预览

【"不要think、强制返回真实描述"怎么落的】
  · 新增提示词 `file_view.STRICT_PROMPT`：只输出真看到的、逐条抄录文字、
    禁推测/禁补全/禁评价/禁客套/禁思考过程，看不清就写「无法辨认」。
  · `VisionClient.describe_strict()`：用它 + `max_tokens` 提到 900（要抄字，300 不够），
    并且对 **deepseek 推理模型显式 extra_body={"thinking":{"type":"disabled"}}**
    —— 不关思考的话 reasoning 会把 token 吃光、content 为空，
    这正是 1.7.1 在长期记忆上踩过的同一个坑。
  · 新增 `get_vision_client()` 单例（工具层没有 UI，拿不到 main_window 里那个实例）。

【接入】
  · `file_ops` 新增 **view** 动作（enum + 参数 + 描述都写清楚了），
    `read` 保留（要逐字原文时用）。
  · 对话提示词第 8 条改成"看文件**优先用 view**"，并说明 pages/method 怎么用。

【实测（真实文件跑通，自测里常态保留）】
  · 文本 README.md：原文直读 17528 字；max_chars=200 时正确抽样并写明省略
  · 图片（注入假视觉）：走 multimodal、收到的是 STRICT_PROMPT、拿到真实尺寸

  · 视觉"禁思考"：deepseek → 加 extra_body；普通模型 → 不加

【四、★"python.exe - 应用程序错误"弹窗：根因找到并修掉了】
────────────────────────────────────────────────────────────────

**根因**：`ToolManager` 的空闲检查线程是 daemon，**退出时没人管它**。主线程
（或 os._exit → ExitProcess 的 DLL 卸载）开始拆进程时，它还在 sleep/wait 或遍历
工具表 → 两边抢 → 访问违例。Windows 随即弹模态框，**框没人点就永远不退出** ——
这就是历次"跑测试挂死、控制台卡住、留下一堆 0 内存僵尸进程"的同一个根因。
**修法（产品侧 + 测试侧都修）**：
  1) `tool_manager.py`：等待改成**可唤醒的 `Event.wait(5)`**；
     `_stop_idle_checker()` 变成"置标志 + 唤醒 + join(timeout)"；循环体加 try/except。
  2) `main_window.py`：退出流程**补上 `get_tool_manager().shutdown()`** ——
     以前主程序退出只关了 TTS，**根本没关工具管理器**（桌宠本体同样有这个隐患）。
  3) `_test_a190.py`：先停线程再退出；并且改用 `TerminateProcess` 而不是
     `os._exit()`（后者会走 ExitProcess → 触发 Qt6 静态析构 → 照样崩，日志里那句
     `QThreadStorage: entry 0 destroyed before end of thread` 就是它）。
     ★ ctypes 必须显式声明 argtypes：HANDLE 是 64 位，默认按 c_int 处理会把
       `GetCurrentProcess()` 的伪句柄截断 → 调用**静默失败**（我踩了一次才修对）。
  4) 测试进程统一注入 `SetErrorMode(SEM_NOGPFAULTERRORBOX)`（见下节）
     —— 以后万一还有别的套件崩，也**不会再弹框打扰你**。

    ① **命令全都送到了子进程**（不是丢消息、不是进程死了）；
    ② 子进程日志里**一条 `[形象自愈]` 都没有** —— 说明自愈看门狗认为一切正常
       （`isVisible()` 真、`isMinimized()` 假）。
  → 所以是那种状态：**Qt 认为窗口可见，但它实际没被合成到屏幕上**。
    而对一个"Qt 认为已经可见"的窗口再调 `show()`，Qt 认为是**空操作**，
    什么都不做。这就是为什么你连点 6 次"显示"都没反应。

  【修法】把子进程的 `show` 命令改成**强制重新映射**：
        `if pet.isVisible(): pet.hide()` → `pet.show()` → `raise_()` → `repaint_current()`
    先 hide 再 show，逼着原生窗口重新创建/映射一次 —— 这是你日志里唯一
    被证实有效过的动作。（代价：对一个本来就正常的形象点"显示"会多一次
    重建，肉眼基本看不出来。）

  【同时补上"下一次能一次定位"的证据】show 之后会把窗口**真实状态**打进日志：
        `| visible=True minimized=False state=0 exposed=True geo={...}`
    —— 其中 `exposed`（`QWindow.isExposed()`）是关键：它比 `isVisible()`
    更接近"到底有没有真的显示在屏幕上"。下次再复现，日志里直接就能看到
    那一刻 `exposed` 是什么，不用再靠猜。
    ⚠ **我没法保证这次一定修好**（这是 Windows 分层窗口的老毛病，我这边
      无法复现）；但至少从"点 6 次都没用"变成"每次点都会强制重建一次"，
      而且无论好没好，下一次的日志都会给出铁证。

── 2. 托盘「显示」不强制显示（你说"成功一半"）───────────────
  同一个根因：`显示桌宠` 只调了 `pet.show()`，在"Qt 说已可见"的状态下
  同样是空操作。现在走上面那条强制重新映射的路，**显示就真的强制显示**。

  说明主进程侧的显隐记账已经生效（这也是"该不该自动救"的判断依据）。
