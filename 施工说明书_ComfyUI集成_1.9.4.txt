 施工说明书：把 ComfyUI 做成「桌宠的私有画图能力」
 1.9.4 · 用户 2026-10-06 的原话：「comfyUI 就完全从项目剥离作为第三方功能，
   用户需要这个功能时，桌宠再实现，你只需要写一份施工说明书，
   让桌宠少走错路就行了。」
──────────────────────────────────────────────────────────────────

【这份文件的用途】
  现在项目里那套画图工具（`tools/comfyui_tool.py` + `src/core/comfyui_client.py`
  + `src/core/comfyui_jobs.py`）**假设用户已经自己跑着 ComfyUI**。
  将来要做"桌宠自己帮用户装好并接管"，照这份做，别重走弯路。

  ★ 相关评估见 `评估_画图工具自部署_1.9.4.txt`（可行性/风险/三步走）。
    这份是**施工**，那份是**判断**。


──────────────────────────────────────────────────────────────────
 一、现状（别跳过，这决定了工作量）
──────────────────────────────────────────────────────────────────
  · `comfyui_client.py` 干的事：往 `127.0.0.1:8188` 发 prompt、轮询、取图。
    **这部分完全不用改** —— 它只认"有个服务在 8188"。
  · 所以新增的东西是**在它前面加一层"部署器"**，不是重写客户端。
  · 耦合面（动它之前先看这里）：
      src/ui/main_window.py        15 处引用
      src/core/tool_manager.py      7 处（工具注册）
      src/ui/direct_dispatch_window.py  5 处
      tools/dev_tests/_test_comfyui_191.py  **87 条断言**
    ★ **现在动它会红 87 条断言** —— 所以"剥离"要**等新工具能顶替之后再删**。


──────────────────────────────────────────────────────────────────
 二、要新建的模块（建议名字与职责）
──────────────────────────────────────────────────────────────────
  src/core/comfyui_provision.py      ← 部署器（本说明书的主角）
      · detect()           探测：GPU/显存/磁盘（**复用 src/core/hardware.py**）、
                           8188 通不通、装在哪
      · plan(hw)           选包：nvidia / AMD / CPU 三套里选哪个；
                           磁盘不够 25GB 就**直接拒绝**并说明
      · download(url,sha256, dest)   **先下临时名、校验 sha256、再改名**
      · extract(archive, dest)       需要 7z（见第四节）
      · install_models(plan)         画图模型（**清单驱动**，见第三节）
      · install_workflow()           放预设 workflow JSON
      · launch() / wait_ready(timeout)   起服务并轮询 8188
      · rollback()          **半装回滚**（删临时目录 / 恢复旧状态）

  data/自建工具模板/             ← 旧工具退役后的归档处
      （目录已建好，见那里的 README.md —— **先并存、后删除**）


──────────────────────────────────────────────────────────────────
 三、★★ 必须维护一份「清单」，否则半年后静默失效
──────────────────────────────────────────────────────────────────
  新建 `src/core/comfyui_manifest.json`（或 .py 里的常量），每项形如：

      {
        "key": "comfyui_portable_nvidia",
        "label": "ComfyUI（NVIDIA 便携版）",
        "url":  "https://github.com/comfyanonymous/ComfyUI/releases/download/<固定tag>/ComfyUI_windows_portable_nvidia.7z",
        "sha256": "<64 位十六进制>",
        "size_mb": 1500,
        "requires": {"gpu": "nvidia", "disk_gb": 25}
      }

  ★★ 为什么必须 sha256：
     GitHub / Civitai / HF 的直链**会变、会限流、有的要 token**。
     没有校验，出问题时的现象是"下了一半的文件被当成好的"，
     **最难查**。下载完**先校验、通过才改名**。

  ★★ 模型同理，而且更麻烦：
     画图模型（用户指定用 **NewBie**，要适配预设工作流）多数在 Civitai，
     直链常带 token、有时要登录。**如果拿不到稳定直链**，
     就只做"引导用户自己下 + 扫路径"（引导里那套 `probe_dir` 已经能扫，
     而且**已改成不限深度** —— 模型散装在 ComfyUI 里也找得到）。


──────────────────────────────────────────────────────────────────
 四、必须踩过才知道的坑（按会让人返工的程度排）
──────────────────────────────────────────────────────────────────
  1. ★★★ **半装比没装更糟**
     下到一半断了 → 留 5GB 残骸；下次启动若误判成"装好了"，
     用户会遇到完全看不懂的行为。
     ⇒ **先下临时名 → 校验 → 改名**；并且**能一键回滚**。
       （`tools/model_manager.py` 的 `migrate` 用的就是这套，直接照抄。）

  2. ★★★ **只认 NVIDIA 就别装 CPU 版**
     `nvidia-smi` 拿不到显卡时，**如实说"你的显卡我认不出来，请自己装"**。
     硬装 CPU 版 = 慢到用户以为坏了，比不装伤害更大。

  3. ★★ **7z 解压**
     便携包是 `.7z`。Python 侧可加 `py7zr`，或随包带一个 `7za.exe`（约 1MB）。
     **不要**指望系统装了 7-Zip。

  4. ★★ **起子进程必须隐藏窗口**（本项目已吃过两次亏）
     用 `from src.utils.proc import no_window_kwargs as _nw` 并 `**_nw()`。
     ★ **例外**：如果是"替用户启动一个**应用**"（用户要看见窗口），
       **不要**隐藏 —— 见 `app_launcher.py` 里那段注释，那里是故意区分的。

  5. ★★ **别在工具线程里碰 Qt 控件**（1.9.2 硬崩过一次，没有 Python 栈）
     进度一律走 Signal 回主线程（`first_run_wizard` 里的 `_sig_line` 是范例）。

  6. ★ **版权**
     我们只做"**替用户下载**"，**不随包分发模型**。
     模型各自有许可，有的禁止再分发 —— 这条线守住。


──────────────────────────────────────────────────────────────────
 五、推荐的落地顺序（三步，别一次做完）
──────────────────────────────────────────────────────────────────
  第 1 步（零风险，先做）：
      只做 `detect()` + 引导：告诉用户他适不适合、缺什么、要多少磁盘；
      已经装好的（给路径 + 手动启动 + 点检测）走现有那套。
      ★ 硬件判断**已经有现成的**：`src/core/hardware.py::advise_drawing()`。

  第 2 步（中风险）：
      清单 + 校验 + 临时名改名 + **进度显示在界面上** + 失败回滚。
      ★ **先拿 Ollama 当试点**（来源稳定、体积小）——
        这套架子已经在 `src/core/llm_local.py` 里跑通了，**照它的形状做**。

  第 3 步（低风险）：
      把旧画图工具**复制**进 `data/自建工具模板/`（先并存），
      新工具能出图之后再删原件、同步删那 87 条断言。
      ★ 这个项目吃过"删得比顶替快"的亏（1.9.3 第 42 轮：一次删 438 行，
        打破 3 条断言，整批回滚）。


──────────────────────────────────────────────────────────────────
 六、验收标准（做到了才算完）
──────────────────────────────────────────────────────────────────
  □ 在一台**没装过 ComfyUI** 的机器上，从零到出图成功一次（真机，不是沙箱）
  □ 中途断网/断电 → 再次启动**不会**误判成装好；能回滚干净
  □ 显卡认不出来的机器 → **明确告知**，不硬装 CPU 版
  □ 磁盘不足 → **拦在下载之前**，不浪费用户时间
  □ 全过程**看得见进度**（用户不用猜它在干什么）
  □ 全量回归 FAIL=0，且旧的 87 条断言是**在新工具能用之后**才删的
