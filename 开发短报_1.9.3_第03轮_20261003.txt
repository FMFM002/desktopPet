**但这轮 log 里挖到一个我们自己的真 bug：render 每次都写一段"崩溃 dump"。**

`logs/main_faulthandler.log` 里，**每做一次 render 就多一段**：

```
Windows fatal exception: code 0x80010108
  ...（一百来行全线程栈）
Current thread ...:  tools/pptx_tool.py line 771 in _do_render
```

第 771 行正是 **`pythoncom.CoUninitialize()`**。
**原因**：pywin32 的 COM 指针是**跟着 Python 对象被 GC 才释放**的，
而 `CoUninitialize()` 会**先把本线程的 COM 套间拆掉** —— 那些还没释放的对象随后再释放，
就报 `RPC_E_DISCONNECTED`。我们的收尾顺序是 `Close()` → `Quit()` → `CoUninitialize()`，
中间**没有丢掉引用**，正好踩中。渲染本身没坏（每次 `success: true`），
但日志里天天多一段"致命异常"，看着像崩了。

**已修**：改成 `Close()` → `Quit()` → **丢引用 + `gc.collect()`** → `CoUninitialize()`。

**实测验证**：

```
修后：跑一次 7 页 render → main_faulthandler.log 增长 0 字节 ✅
```

**验证**：`_test_pptx_render_193` **67 → 70 断言**（新增源码顺序守卫：丢引用必须排在
`CoUninitialize()` 之前、注释里留着 `0x80010108` 证据、该收尾的仍要收尾）；
compileall 0；**全量回归 48 套件 FAIL=0**。

**另外两条记档（都不是 bug）**：模型曾自言自语"描述说共6页但实际7页"——复核过，
