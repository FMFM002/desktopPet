==============================================================================
PTRTS1.9.0 —— 工具能力说明书（tools 功能 / 参数 / 返回）
==============================================================================
说明：
  · 本文件是**给人和给 LLM 看的速查**；真正的参数 schema 由各工具源码里的
    `get_parameters()`（或 PARAMETERS）定义，运行时由 ToolManager 扫描 tools/*.py 生成。
  · 所有工具统一返回**字符串**；绝大多数是 JSON 文本，字段以 `success` 打头：
        成功 -> {"success": true,  ...业务字段...,  "text": "给 LLM 看的可读摘要"}
        失败 -> {"success": false, "error": "失败原因（可操作）"}
  · 工具策略：`resident` = 常驻内存；`lazy` = 首次调用才加载，空闲会被卸载。
  · 每次调用都会把结果回灌给 LLM（`text` 字段就是给人看的那段）。
  · ★ 1.9.0 约定：如果一次调用希望桌宠换个动作表情，可在返回 JSON 里加
        "gif": "<角色GIF名>"   （"0" 或省略 = 保持当前形象动作）
    会话层会读它并切换形象（见《行为控制》一节的说明）。

■ web_search
──────────────────────────────────────────────────────────────────────────────
【用途】
  联网搜索。需要给用户看图时：拿结果里的图片链接交给 download 下载并发聊天。

【完整描述（LLM 看到的就是它）】
  联网搜索信息。传入关键词进行网络搜索，返回搜索结果摘要与相关图片链接。★ 需要把图片发给用户时：拿到结果里的图片链接后，调 download 工具(url=图片链接) 把图下载下来，它会自动显示在聊天窗口里。

【参数】
  · query  (string, **必填**)
      说明: 搜索关键词
  必填项: query

【返回】
  JSON 文本；常见字段：（见源码）
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  典型输出片段：
      · 搜索出错: {e}
      · 未找到关于'{query}'的结果
      · 模拟搜索: 关于'{query}'的结果 - 搜索API未配置

【示例】
  web_search({"query": "上海今天天气", "include_images": true})

──────────────────────────────────────────────────────────────────────────────
■ download
──────────────────────────────────────────────────────────────────────────────
【用途】
  把任意 http/https 链接下载到 data/downloads/<来源>/，并自动发到聊天窗口。
  ★ 1.9.2 起：支持多线程分段 + 断点续传（照 Motrix），
    也支持 BT / 磁力链（交给 aria2c 后台下载）。

【完整描述（LLM 看到的就是它）】
  把任意 http/https 链接（图片、封面、PDF、压缩包、音视频等）下载到本地，并自动发送到聊天窗口。★ 支持多线程分段下载 + 断点续传（照 Motrix）：大文件会切成多段并发拉取，下到一半中断的话，再下同一个 URL 会接着下（不会从头再来）。★ 也支持 BT：磁力链（magnet:?xt=urn:btih:…）和 .torrent 种子，交给 aria2c 后台下载（BT 很慢，会立刻返回 job_id，之后问进度就行）。联网搜索拿到图片链接后要用它把图取回来；B站封面、网页上的附件同理。参数: url(必填); filename(可选，含扩展名); bucket(可选，默认 websearch); threads(可选，分段并发数 1-8，默认自动); resume(可选，默认 true); max_mb(可选，默认 512); action(可选: 空=下载 | bt_status=看 BT 任务进度 | bt_stop=停止，配 job_id)。

【参数】
  · url  (string, **必填**)
      说明: 普通 http/https 链接 / 磁力链 magnet:?xt=… / .torrent 种子
  · filename  (string, 可选)
      说明: 保存的文件名（含扩展名）；不填则从 URL 推断
  · bucket  (string, 可选)
      说明: 保存到 data/downloads/ 下的哪个子目录，默认 websearch；BT 落到 <bucket>/bt/
  · threads  (integer, 可选)
      说明: 分段并发数 1-8；0 或不填=自动（按文件大小定）
  · resume  (boolean, 可选)
      说明: 断点续传，默认 true；中断后再下同一 URL 会接着下（实测只补缺失分段）
  · max_mb  (integer, 可选)
      说明: 大小上限（MB），默认 512
  · referer  (string, 可选)
      说明: 防盗链站点需要（如 B站封面填 https://www.bilibili.com）
  · action  (string, 可选)
      可选值: (空) / bt_status / bt_stop / bt_engine
      · bt_status 查 BT 任务进度；bt_stop 停任务（配 job_id）；bt_engine 看引擎状态
  · job_id  (string, 可选)
      说明: 只对 action=bt_stop 有意义
  必填项: url

【返回】
  JSON 文本；常见字段：success, file_path, file_name, file_size, bytes,
  is_image, url, mode, threads, seconds, speed, message
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  BT：{"success": true, "bt": true, "job_id": "bt-…", "dir": "…"}
  ★ 断点续传：中断时返回 {"success": false, "resumable": true,
     "partial_file": "xxx.part", "hint": "再调用一次同一条 download 即可续传"}
  ★ BT 引擎缺失时返回 {"success": false, "bt": true,
     "error": "……需要 aria2c……三种放置办法……"}（绝不会自动下载安装）
  典型输出片段：
      · 🖼 图片下载完成 · xxx.png · 145 B
      · 📎 下载完成 · xxx.zip · 3.0 MB · 4 段并发
      · 🧲 已开始后台下载磁力链（job bt-…）

【示例】
  download({"url": "https://…/a.jpg", "filename": "封面.jpg"})
  download({"url": "https://…/big.zip", "threads": 8})
  download({"url": "magnet:?xt=urn:btih:c12fe1c06bba254a9dc9f519b335aa7c1367a88a"})
  download({"url": "", "action": "bt_status"})

■ bilibili_video
──────────────────────────────────────────────────────────────────────────────
【用途】
  B站：info=视频信息、cover=封面下载并发聊天、download=下载视频（含音频）。

【完整描述（LLM 看到的就是它）】
  B站视频信息查询与下载工具。当用户分享B站链接、BV号、b23.tv短链接时使用。支持: info(查询视频信息)、cover(下载封面到本地并显示在聊天窗口)、download(下载视频)。

【参数】
  · action  (string, 可选)
      可选值: info, cover, download
      说明: info=查询视频信息, cover=下载封面（会自动显示在聊天窗口）, download=下载视频
  · bv_id  (string, 可选)
      说明: BV号(不含BV前缀)，如 1k24y1B7Ef
  · raw_message  (string, 可选)
      说明: 原始消息文本，用于自动提取BV号/短链接
  必填项: 无

【返回】
  JSON 文本；常见字段：action, error, file_path, pages, success, title, url
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  典型输出片段：
      · BV{m.group(1)}
      · {bvid}_封面{suf}

【示例】
  bilibili_video({"action": "cover", "bvid": "BV1xx411c7mD"})

──────────────────────────────────────────────────────────────────────────────
■ file_ops
──────────────────────────────────────────────────────────────────────────────
【用途】
  文件操作总入口：view 看内容、read 读原文、write 写、edit 改、search 搜、list 列目录、send 发到聊天。view 支持指定页/抽样/多模态/OCR/STT。

【完整描述（LLM 看到的就是它）】
  文件操作工具集。支持: 查看文件、读取原文、写入、编辑、搜索、列出目录、发送文件到聊天窗口。通过action参数选择操作类型。★ 要看文件内容用 view（推荐）：它会按文件类型和大小**自动选路** —— 图片/扫描件直接走多模态**如实描述**（禁思考、不编造）；大文件自动抽样；可以指定 pages 只看某几页（如 "3" 或 "3-5"）。★ 要逐字原文用 read（文本/代码/PDF/Word/Excel/PPT 都能抽文本）。用户发来的文件或提到的本地文件路径，你都可以（也应该）去看，不要说「我看不到文件/我没有眼睛」——看文件就是你的眼睛。要把文件发给用户时用 send 操作。

【参数】
  · action  (string, **必填**)
      可选值: view, read, write, edit, search, list, send, list_downloads
      说明: 操作类型: view(统一查看文件内容，推荐), read(读原文), write(写入), edit(编辑), search(搜索), list(列表), send(发送文件到聊天窗口), list_downloads(列出下载目录中的文件)
  · path  (string, 可选)
      说明: 文件/目录路径。[send] 需要发送的文件的完整路径
  · content  (string, 可选)
      说明: [write] 写入内容
  · old_string  (string, 可选)
      说明: [edit] 要替换的旧文本
  · new_string  (string, 可选)
      说明: [edit] 替换后的新文本
  · offset  (integer, 可选)
      说明: [read] 起始行号
  · limit  (integer, 可选)
      说明: [read] 读取行数
  · method  (string, 可选)
      可选值: auto, multimodal, vision, stt, text
      说明: [view] 查看方式: auto(自动选路，默认) / multimodal(多模态直读) / vision(视觉识别) / stt(语音转写) / text(本地看原文)
  · pages  (string, 可选)
      说明: [view] 查看位置: 空=默认(超过8页自动抽样) / "3"=第3页 / "3-5"=第3到5页 / "1,4,7"。PDF按页、PPT按张、Excel按工作表
  · max_chars  (integer, 可选)
      说明: [view] 返回文本上限（默认 20000 字，超出自动抽样头尾）
  · prompt  (string, 可选)
      说明: [view] 自定义视觉提示词（一般不用填，默认强制如实描述）
  · pattern  (string, 可选)
      说明: [search/list/list_downloads] 搜索模式或文件过滤
  · file_types  (string, 可选)
      说明: [search] 文件类型过滤
  · case_sensitive  (boolean, 可选)
      说明: [search] 区分大小写
  必填项: action

【返回】
  JSON 文本；常见字段：action, count, file_path, files, message, pages, success
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  典型输出片段：
      · [拒绝] 禁止修改关键配置文件: {os.path.basename(full_path)}
      · [未找到] {path}: 文件不存在
      · [错误] old_string在文件中未找到。请确保文本完全匹配（包括空格、换行）。

【示例】
  file_ops({"action": "view", "path": "D:/x.pdf", "method": "multimodal", "pages": "3"})
  file_ops({"action": "write", "path": "D:/a.txt", "content": "hi"})

■ office
──────────────────────────────────────────────────────────────────────────────
【用途】
  创建/编辑 Word(docx)、Excel(xlsx)、PowerPoint(pptx)。

【完整描述（LLM 看到的就是它）】
  Office文档操作工具，支持创建和编辑 Word(.docx)、Excel(.xlsx)、PowerPoint(.pptx) 文件。基于OfficeCLI命令行，可创建文档、添加幻灯片/表格/形状/文字/图片、修改属性、查看大纲。支持的操作: create(创建空白文档), add(添加元素), set(修改元素), view(查看大纲/内容), batch(批量JSON操作)。生成的文件保存在 桌宠私有data/office/ 下的对应子文件夹(pptx/docx/xlsx)中，用完后可调用file_ops的send操作发送到聊天窗口。注意: 图片路径必须使用本地绝对路径，图片素材在data/downloads/目录下，可先用shell_exec下载图片。

【参数】
  · action  (string, **必填**)
      可选值: create, add, set, view, get, batch, help, install
      说明: 操作类型
  · file  (string, 可选)
      说明: 文档路径(相对于data/downloads/)，如 'report.pptx'、'data.xlsx'
  · format  (string, 可选)
      可选值: pptx, docx, xlsx
      说明: 文档格式（仅 create 时需要）
  · path  (string, 可选)
      说明: 元素路径，如 '/' 表示根、'/slide[1]' 第一张幻灯片、'/slide[1]/shape[1]' 第一个形状
  · type  (string, 可选)
      说明: 添加的元素类型: slide(幻灯片), shape(形状/文本框), image(图片), sheet(工作表), table(表格), paragraph(段落)
  · props  (object, 可选)
      说明: 属性键值对。PPT常用: title(标题), text(文字), x/y(位置如'2cm'), w/h(宽高), font(字体), size(字号), color/fill(颜色), background(背景色), bold(加粗)。Excel: name(表名), value(值), formula(公式)。图片: src(本地图片绝对路径)
  · mode  (string, 可选)
      可选值: outline, text, html
      说明: view 查看模式
  · commands  (array, 可选)
      说明: batch操作的JSON命令数组，每条命令含op(操作:add/set/remove)和对应参数。示例: [{"op":"add","path":"/","type":"slide","props":{"title":"标题"}}]
  · data  (object, 可选)
      说明: merge模板合并时的JSON数据
  必填项: action

【返回】
  JSON 文本；常见字段：action, error, message, mode, success, text
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  典型输出片段：
      · OfficeCLI 安装成功，路径: {found}
      · 修改失败: {result.get('error', '未知错误')}
      · 创建失败: {result.get('error', result.get('text', '未知错误'))}

【示例】
  office({"action": "create", "file_type": "docx", "path": "D:/a.docx", "content": "…"})

■ system_command
──────────────────────────────────────────────────────────────────────────────
【用途】
  系统快捷操作：本机/公网IP与归属地、打开应用、系统信息、进程管理、时间日期、磁盘内存等。

【完整描述（LLM 看到的就是它）】
  执行快捷系统操作。支持: 查本机/公网IP、打开应用、查询系统信息、进程管理、时间日期、磁盘内存等。

【参数】
  · action  (string, **必填**)
      可选值: get_ip_info, get_local_ip, open_calc, open_notepad, open_explorer, open_browser, system_info, get_time, list_processes, disk_usage, memory_usage, kill_process, open_url
      说明:
        - get_ip_info  ★推荐。本机内网IP + 公网IP + 归属地（国家/省份/城市/运营商/ASN/时区/经纬度）
        - get_local_ip 只要局域网IPv4（ipconfig里那个）
        - get_time     当前日期+时间（含星期与周数）
        - 其余: open_calc / open_notepad / open_explorer / open_browser / system_info /
          list_processes / disk_usage / memory_usage / kill_process / open_url
      注: 原 get_date 与 get_time 功能重复，1.9.2 已合并为一个；get_date 仅作旧调用别名保留，不在枚举里暴露。
  · param  (string, 可选)
      说明: [open_url/open_explorer/kill_process] 额外参数
  必填项: action

【返回】
  JSON 文本；常见字段：action
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  get_ip_info 典型输出：
        内网IP: 10.x.x.x
        主机名: <主机名>
        公网IP: 45.x.x.x
        国家: 中国 / 省份: 香港特别行政区 / 城市: 香港
        运营商: Catixs Ltd / ASN: AS48266 Catixs Ltd
        时区: Asia/Hong_Kong / 经纬度: 22.374, 114.1369
  数据源: 主 ipapi.co(HTTPS)，备 ip-api.com；两者都免 key。查询失败只影响公网部分，内网IP照常返回。
  典型输出片段：
      · [提示] psutil未安装
      · [提示] psutil未安装，无法列出进程
      · [错误] kill_process 需要进程名或PID参数

【示例】
  system_command({"action": "get_ip_info"})
  system_command({"action": "get_local_ip"})
  system_command({"action": "get_time"})

■ shell_exec
──────────────────────────────────────────────────────────────────────────────
【用途】
  执行终端命令（Windows=cmd 语法），返回 stdout/stderr。

【完整描述（LLM 看到的就是它）】
  执行终端/shell命令并返回stdout和stderr。Windows用cmd语法，Linux/macOS用bash语法。★ 沙箱限制：用户电脑全盘只读，仅 data/桌宠私有data 目录可写可读。写入/下载/生成的文件请使用绝对路径 data/桌宠私有data/... 或先 cd 到该目录。★ Windows重要提示: 临时文件请写到 data/桌宠私有data/，不要用 /tmp/（Windows 不存在 /tmp/）。限制: 超时60秒、输出≤50000字符。

【参数】
  · command  (string, **必填**)

  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}

      · [错误] 命令未找到: {command}

■ knowledge_graph
──────────────────────────────────────────────────────────────────────────────
【用途】
  结构化知识的存取与查询（本地图谱文件）。

【完整描述（LLM 看到的就是它）】
  知识图谱工具，用于存储和查询结构化知识。支持:
  - analyze_project: 分析代码项目结构，自动生成知识图谱和 HTML 可视化

  · description  (string, 可选)

  · properties  (string, 可选)

  · source  (string, 可选)
      说明: [add_relation/query_relation] 源实体名称
  · target  (string, 可选)
      说明: [add_relation/query_relation] 目标实体名称
  · relation  (string, 可选)
      说明: [add_relation] 关系类型，如 knows/contains/depends_on/related_to/part_of/imports/calls/inherits
  · rel_description  (string, 可选)
      说明: [add_relation] 关系描述（可选）
  · query  (string, 可选)
      说明: [search] 搜索关键词
  · entity_type_filter  (string, 可选)
      说明: [list_types/search] 按类型过滤（可选）
  必填项: action

【返回】

■ meme
──────────────────────────────────────────────────────────────────────────────
【用途】
  发表情包。想表达情绪时调用一次，它会挑一张进「待发送」队列；你的文字回复
  结束后，主窗口会**单独发一条**表情包（不是混在文字里）。

【完整描述（LLM 看到的就是它）】
  发表情包。想在回复里表达情绪时调用一次：它会挑一张表情包并进入待发送状态，
  你的文字回复结束后会自动单独发出去（表情包最后发）。一轮里只会生效一次，
  别重复调用。参数 tag 可选（happy/angry/sad/shy/daily/confused/surprised/
  like/see/cpu/color 等），name 可选（直接指定文件名）。

【参数】
  · tag  (string, 可选)
      说明: 想表达的情绪标签，例如 happy/angry/sad/shy/daily
  · name  (string, 可选)
      说明: 直接指定文件名（如 009.webp），给了就以它为准
  · reason  (string, 可选)
      说明: 为什么发这张（只记日志，不发给你）
  必填项: 无

【返回】
  JSON 文本；常见字段：action, meme, path, success, tag, text
  失败时: {"success": false, "error": "…（会写清原因和补救办法）"}
  典型失败:
      · 本轮已经选过表情包了（xxx），一轮只生效一次
      · 找不到表情包「xxx」。请用目录里列出的文件名，或改用 tag 让我自己挑
      · 当前角色的「行为控制 → 表情包倾向」是「不发」

【示例】
  meme({"tag": "happy", "reason": "用户夸了我"})

【给 LLM 的调用纪律（写进系统提示词的那几条）】
==============================================================================
  1. 能一次说清就别连着调好几个工具；同一轮里同一种工具别重复调。
  2. 要看图片/PDF/Office/音频内容 → 一律用 file_ops 的 view（不要再试图「直接看图」）。
  3. 拿到 URL 要落地成文件（发给用户）→ download，别自己写脚本爬。
  4. 工具失败时 `error` 里通常已经写了补救办法，照着它改参数重试一次即可。
  5. 想让形象换动作 → 在返回里带 "gif"（或直接在思考末尾输出 {"gif": "…"}）。
