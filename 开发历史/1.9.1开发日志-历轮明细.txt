── 3. ★★ 顺手抓到并修掉的三个真 bug（全是自测抓的，不是猜的）────
  【bug 1：job_id 撞号 → 有图凭空消失】
    `job_id` 原来用 `draw-{毫秒时间戳}`。连着提交两张（手快、或模型一轮调两次）
    极容易落在同一毫秒 → `_jobs[job_id]` **被覆盖**、队列里同一个 id 出现两次
    → **其中一张永远画不出来**。
    自测现场：提交 X/Y/Z 三张，`_submitted` 里只有 X 和 Z，Y 没了。
    → 改成 **进程内自增序号 + 毫秒**，锁内取号，不可能重复。
  【bug 2：`wait_all()` 会提前返回】
    原来判断"队列空了"用 `_queue.empty() and not _current`。
    但 worker 在 `_queue.get()` 和 `_current.update()` 之间有**极短空隙**，
    这时两边看着都空 → 提前返回 True（自测里"两张只跑了一张"就报跑空）。
    → 改成在锁内看**任务状态表**（有没有 queued/running）。
  【bug 3（不算 bug 但会误导）：排队位次报错】
    原来用 `_queue.qsize() + 1`。worker 一取走上一张，两张就都报"第 1 位"。
    → 改成锁内数"还在排队等着的" + 1。语义也更对：前面那张在画了，你就是队首。

###优化老bug：系统图片查看器退出时导致形象消失。
根因：系统图片查看器全屏进出时，DWM 丢掉桌宠分层窗口的合成状态。

三点思路：

1. 改窗口样式，让 DWM 始终合成
      加 WS_EX_COMPOSITED（始终整体合成）+ WS_EX_NOACTIVATE（不抢焦点、不被取消激活）。
      → 从源头避免被 DWM 丢掉。
2. 监听 DWM 合成变化，收到就重新声明
      注册 WM_DWMCOMPOSITIONCHANGED，一旦 DWM 合成模式切换，立刻重设样式 + 强制重绘。
      → 全屏应用进出时自动恢复，不依赖任何外部事件。
3. （可选，最彻底）换掉分层窗口
      用 WS_EX_NOREDIRECTIONBITMAP 替代 WS_EX_LAYERED，走 DirectComposition。
      → 机制上不存在“分层表面失效”。改动大，前两步压不住再上。

一句话：不靠事后兜底，而是让窗口从一开始就不被 DWM 丢掉；1 是常态保障，2 是模式切换保障，3 是终极替换。你研究研究。

── 3. ★★ 老 bug 研究：全屏进出后形象消失（你给的思路我逐条核对了）──
  你给了三条思路让我"研究研究"。我查了 MSDN 原文，**逐条核对结果如下**
  （都写进了 `src/ui/win_window.py` 的文件头 + 固化成回归断言）：

  【思路 1「WS_EX_COMPOSITED + WS_EX_NOACTIVATE，让 DWM 始终合成」】
    · `WS_EX_COMPOSITED` —— **不对症，没采用**。MSDN 定义是
      "Paints all descendants of a window in bottom-to-top painting order using
       double-buffering" —— 它管的是**子窗口**的绘制顺序/半透明
      （还要求子窗口带 WS_EX_TRANSPARENT），跟"顶层分层窗口被 DWM 丢掉"是两回事；
      文档另外写明**窗口类带 CS_OWNDC / CS_CLASSDC / CS_PARENTDC 时不能用**。
      所以我把它做成**默认关闭的开关**（`USE_COMPOSITED=False`），
      想真机 A/B 对比时再开，而不是直接塞进去赌一把。
    · `WS_EX_NOACTIVATE` —— **有用，已采纳**。文档：带此样式"点击它不会成为前台窗口"。
      桌宠本来不需要焦点，加上之后**点形象不抢你正在用的程序的焦点**，是实打实的改进。

  【思路 2「监听 WM_DWMCOMPOSITIONCHANGED，收到就重设样式 + 强制重绘」】
    · ★★ **在你要用的系统上永远不会触发**。MSDN 原文注意事项：
      "从 Windows 8 起，DWM 组合始终处于启用状态，因此**无论视频模式如何更改，
       都不会发送此消息**。"（你这台 RTX 5060 + Win10/11，必然收不到）
    · 但**这个思路的意图是对的**（环境一变就重新声明窗口状态），
      所以我换到**真的会发**的信号上：
        · `WM_DISPLAYCHANGE`(0x007E)——显示模式/分辨率变化，全屏进出常常触发
        · `WM_DPICHANGED`(0x02E0)——DPI 变化
        · **`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`**——前台窗口变化，
          现代 Windows 上"某个程序全屏了/退出了"最可靠的信号
          （实测装上去立刻抓到了前台窗口变化，说明可靠）
        · 加上子进程原有的看门狗兜底
      收不到的那条 `WM_DWMCOMPOSITIONCHANGED` 我**保留**了处理分支，但注释写明
      "Win8+ 收不到，别指望它"——将来给旧系统用。

  【思路 3「（最彻底）WS_EX_NOREDIRECTIONBITMAP 替代 WS_EX_LAYERED，走 DirectComposition」】
    · **在 Qt Widgets 上不可行，没做**。文档定义：
      "The window does not render to a redirection surface. This is for windows that
       do not have visible content or that use mechanisms other than surfaces"
      —— 也就是**这个窗口必须自己用 DirectComposition 提供画面**。
      而 Qt Widgets 是用 QPainter/GDI 往重定向表面画的，换上去的结果是
      **窗口直接什么都不显示**。真要走 = 把渲染栈换成 Qt Quick + DComp 后端
      （或自绘 D3D），成本远大于收益。

  【我实际做了什么】
    · 新增 `src/ui/win_window.py`：全部 Win32 调用集中在这里，
      非 Windows 空操作、任何调用失败都吞掉只记 debug ——
      **绝不让异常冒到 Qt 事件循环**（1.9.1 已经因为"一条命令抛异常弄死子进程"吃过亏）。
    · `snapshot()` / `snapshot_str()`：**把现场测准**。以前失败时日志里一点证据都没有，
      只能靠猜着换方案。现在每次触发都打一份状态快照：
        是否可见 / 是否被最小化 / 还是不是 topmost / 还是不是分层窗口(WS_EX_LAYERED)
        / 有没有 NOACTIVATE / 矩形位置 / **当前前台窗口是谁、标题是什么**
      ——下次真复现时，一眼就能看出是"丢了 topmost"、"被最小化"还是"表面失效"。
    · `reassert()`：按真实状态对症修（最小化→SW_RESTORE；丢 topmost→重新声明；
      再 SWP_FRAMECHANGED + RedrawWindow 强制整体重画），**并打印修复前后的快照**。

能。但“彻底解决”不是再加一层兜底，而是**让窗口从一开始就不会被 DWM 丢掉合成状态**。你这两个场景已经证明：窗口本身没坏，托盘“显示”能救回来，说明只是 DWM 不再画它。所以要根治，得从窗口样式和 DWM 事件入手。

## 先确认根因

系统图片查看器（`Microsoft.Photos.exe` / `ApplicationFrameWindow`）打开时，它会：

1. 抢前台焦点；
2. 把自己设为全屏/置顶；
3. 可能让 DWM 进入全屏合成模式。

退出时，DWM 恢复桌面合成，但**不会自动重新合成桌宠那个分层窗口**。  
Qt 内部状态仍是“可见”，但 DWM 的合成表面已经失效。  
托盘“显示”走的是 `SetWindowPos` + `ShowWindow`，强制 DWM 重建合成，所以能救回来。

根因一句话：**分层窗口在 DWM 合成模式切换时丢失了合成状态，且没有收到重新合成的通知。**

## 彻底方案：让窗口对 DWM 始终“可合成”

不是事后补救，而是让窗口具备三个属性：

1. **始终被 DWM 合成** —— `WS_EX_COMPOSITED`
2. **不因焦点变化被取消激活** —— `WS_EX_NOACTIVATE`
3. **DWM 合成状态一变就重新声明自己** —— 监听 `WM_DWMCOMPOSITIONCHANGED`

### 1. 设置扩展样式

在形象窗口创建后（`pet_process.py` 里 `show()` 之前）执行：

```python
import ctypes
user32 = ctypes.windll.user32

GWL_EXSTYLE = -20
WS_EX_LAYERED      = 0x00080000   # 保持透明，已有
WS_EX_TOOLWINDOW   = 0x00000080   # 不进任务栏/Alt+Tab
WS_EX_TOPMOST      = 0x00000008   # 始终置顶
WS_EX_NOACTIVATE   = 0x08000000   # 关键：不因焦点变化被取消激活
WS_EX_COMPOSITED   = 0x02000000   # 关键：强制 DWM 始终合成

hwnd = int(pet.winId())
ex = user32.GetWindowLongW(hwnd, GWL_EXSTYLE)
ex |= WS_EX_TOOLWINDOW | WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_COMPOSITED
user32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex)

# 让样式立即生效
SWP_NOMOVE = 0x0002; SWP_NOSIZE = 0x0001
SWP_FRAMECHANGED = 0x0020; SWP_SHOWWINDOW = 0x0040
user32.SetWindowPos(hwnd, -1, 0, 0, 0, 0,
    SWP_NOMOVE | SWP_NOSIZE | SWP_FRAMECHANGED | SWP_SHOWWINDOW)
```

`WS_EX_COMPOSITED` 是关键：它告诉 DWM“这个窗口和它的子窗口始终作为整体合成”，DWM 不会因为别的全屏窗口出现就把它丢掉。  
`WS_EX_NOACTIVATE` 让它不参与焦点争夺，图片查看器抢焦点时它不会被“取消激活”，合成状态自然也不会断。

### 2. 监听 DWM 合成状态变化

即使有 `WS_EX_COMPOSITED`，DWM 在某些情况下仍可能重置合成。加一个原生事件处理：

```python
from PyQt5.QtCore import QAbstractNativeEventFilter
import ctypes
from ctypes import wintypes

WM_DWMCOMPOSITIONCHANGED = 0x031E

class DwmFilter(QAbstractNativeEventFilter):
    def __init__(self, pet):
        super().__init__()
        self.pet = pet

    def nativeEventFilter(self, eventType, message):
        if eventType == b"windows_generic_MSG":
            msg = ctypes.cast(int(message), ctypes.POINTER(wintypes.MSG)).contents
            if msg.message == WM_DWMCOMPOSITIONCHANGED:
                self._reassert_composition()
        return False, 0

    def _reassert_composition(self):
        hwnd = int(self.pet.winId())
        ex = user32.GetWindowLongW(hwnd, GWL_EXSTYLE)
        ex |= WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_COMPOSITED
        user32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex)
        user32.SetWindowPos(hwnd, -1, 0, 0, 0, 0,
            SWP_NOMOVE | SWP_NOSIZE | SWP_FRAMECHANGED | SWP_SHOWWINDOW)
        user32.RedrawWindow(hwnd, None, None,
            RDW_INVALIDATE | RDW_UPDATENOW | RDW_ALLCHILDREN | RDW_FRAME)
```

`WM_DWMCOMPOSITIONCHANGED` 是 DWM 在“合成开/关、全屏应用进出”时广播的。收到就重新声明样式 + 强制重绘，DWM 会重新把它纳入合成。

### 3. 可选但更彻底：换掉分层窗口

如果上面两步还压不住，说明问题出在 `WS_EX_LAYERED` 本身。Windows 8+ 对透明窗口有更现代的方式：

```python
WS_EX_NOREDIRECTIONBITMAP = 0x00200000

ex = user32.GetWindowLongW(hwnd, GWL_EXSTYLE)
ex = (ex & ~WS_EX_LAYERED) | WS_EX_NOREDIRECTIONBITMAP
user32.SetWindowLongW(hwnd, GWL_EXSTYLE, ex)
```

它用 DirectComposition 代替分层表面，**从机制上不存在“分层表面失效”这回事**。  
代价：Qt 侧要配合 `WA_TranslucentBackground` 和 `QSurfaceFormat`，改动比前两步大。建议先试 1+2，不行再上 3。
